# THE MOST IMPORTANT DECISION

The stack was never chosen because the tools were popular.

Every tool exists because it directly supports one of the four core engines:

1. Navigation Engine
2. Medical Knowledge Engine
3. Intelligence Engine
4. Agent Operating System

If a framework does not strengthen one of those engines, it should not exist in the repository.

// src/server/security/ownership.tsimport { prisma } from "@/server/db";import { AppError } from "@/server/errors/app-error";export class OwnershipError extends AppError {  constructor(message = "Resource access denied") {    super(message, 403, "OWNERSHIP_ERROR");  }}/** * Generic assertion helper */function assertOwnership(  condition: boolean,  resource: string): void {  if (!condition) {    throw new OwnershipError(      `You do not own this ${resource}`    );  }}

Passport Ownership
export async function assertPassportOwnership(  passportId: string,  userId: string) {  const passport =    await prisma.healthPassport.findFirst({      where: {        id: passportId,        userId      }    });  if (!passport) {    throw new OwnershipError(      "Passport access denied"    );  }  return passport;}

Resource Resolver
Useful for audit layer.
export async function assertResourceOwnership(  resourceType: string,  resourceId: string,  userId: string) {  switch (resourceType) {    case "passport":      return assertPassportOwnership(        resourceId,        userId      );    case "journey":      return assertJourneyOwnership(        resourceId,        userId      );    case "document":      return assertDocumentOwnership(        resourceId,        userId      );    case "memory":      return assertMemoryOwnership(        resourceId,        userId      );    case "outcome":      return assertOutcomeOwnership(        resourceId,        userId      );    default:      throw new Error(        `Unknown resource type: ${resourceType}`      );  }}

Usage Example
Never:
const passport =  await prisma.healthPassport.findUnique({    where: {      id: passportId    }  });

const passport =  await assertPassportOwnership(    passportId,    session.user.id  );

Design Rule
Every Server Action follows:
1. Authenticate2. Authorize3. Ownership Check4. Execute5. Audit Log6. Analytics Event7. Return Result
Example:
export async function updatePassport(  passportId: string,  input: UpdatePassportInput) {  const session = await auth();  if (!session?.user?.id) {    throw new Error("Unauthorized");  }  const passport =    await assertPassportOwnership(      passportId,      session.user.id    );  const updated =    await prisma.healthPassport.update({      where: {        id: passport.id      },      data: input    });  await audit.log({    actorId: session.user.id,    eventType: "PASSPORT_UPDATED",    resourceId: passport.id  });  return updated;}

// utils.tsexport function calculateDistance(  lat1: number,  lon1: number,  lat2: number,  lon2: number) {  const R = 6371;  const dLat =    ((lat2 - lat1) * Math.PI) / 180;  const dLon =    ((lon2 - lon1) * Math.PI) / 180;  const a =    Math.sin(dLat / 2) *      Math.sin(dLat / 2) +    Math.cos(lat1) *      Math.cos(lat2) *    Math.sin(dLon / 2) *      Math.sin(dLon / 2);  return R * 2 * Math.atan2(    Math.sqrt(a),    Math.sqrt(1 - a)  );}

# DATABASE ARCHITECTURE

## Primary Database

**Amazon Aurora PostgreSQL (AWS)**

Aurora PostgreSQL serves as the system of record for the entire SwasthYatra platform.

All critical healthcare, navigation, provider, organization, and outcome data is persisted in Aurora.

---

## Why Aurora PostgreSQL?

SwasthYatra is not a simple CRUD application.

The platform requires:

* Complex relational data
* ACID transactions
* Geospatial queries
* High availability
* Read scalability
* Automated backups
* Enterprise-grade reliability

Aurora PostgreSQL provides all of these while maintaining full PostgreSQL compatibility.

---

## Why Not Standard PostgreSQL?

While standard PostgreSQL is excellent, Aurora provides:

### Higher Availability

```text
Multi-AZ replication

Automatic failover

Self-healing storage
```

Target Availability:

```text
99.99%
```

---

### Better Scalability

Aurora supports:

```text
Read Replicas

Reader Endpoints

Distributed Storage
```

This allows:

```text
Millions of provider lookups

Passport retrieval

Medication searches

Outcome analytics
```

without overloading the primary writer node.

---

### Managed Operations

Aurora removes operational burden:

```text
Automatic Backups

Point-in-Time Recovery

Storage Scaling

Patch Management
```

The engineering team focuses on product development rather than database administration.

---

## PostgreSQL Extensions

### PostGIS

Aurora PostgreSQL will run with:

```text
PostGIS
```

enabled.

Used for:

* Nearby provider discovery
* Hospital search
* Pharmacy search
* Distance calculations
* Radius-based filtering

Example:

```sql
Find providers within 5km
Find pharmacies open nearby
Find nearest emergency room
```

---

## Database Access Layer

Application access follows:

```text
Next.js
    ↓
Prisma ORM
    ↓
Aurora PostgreSQL
```

Prisma acts as the single database abstraction layer.

No direct SQL queries from application code unless required for performance-critical operations.

# Database Philosophy

Aurora PostgreSQL is not simply a database.

It stores the Healthcare Navigation Graph.

```text
Traveler
    ↓
Journey
    ↓
Passport
    ↓
Memory
    ↓
Medication
    ↓
Provider
    ↓
Interpreter
    ↓
Outcome
    ↓
Healthcare Intelligence
```

As journeys accumulate, the platform becomes increasingly intelligent through its Provider Graph, Medication Graph, and Outcome Graph.
