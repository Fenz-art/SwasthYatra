SWASTHYATRA FRONTEND TRANSFORMATION BRIEF
FROM APPLICATION TO OPERATING SYSTEM

Before touching a single file, understand this:

You are not redesigning a website.

You are not redesigning dashboards.

You are not redesigning a healthcare application.

You are transforming SwasthYatra into the operating system for healthcare navigation.

Read the existing architecture, workflows, routes, backend systems, role structures, and demo experiences thoroughly before making any design decision. The backend, architecture, workflows, Prisma schema, APIs, permissions, and role structures are already complete and correct. They are not part of this project.

Your responsibility is exclusively the frontend experience.

The mission is simple:

Preserve 100% of the product.

Elevate 100% of the experience.

WHAT SWASTHYATRA IS

SwasthYatra is not:

An AI assistant
A healthcare chatbot
A telemedicine platform
A provider marketplace
A provider directory
A medical CRM
A healthcare dashboard

SwasthYatra is:

A Healthcare Navigation Network.

A platform coordinating:

Travelers
Doctors
Pharmacists
Hospitals
Organizations
Operators
Communication Networks
Care Outcomes

into one continuous healthcare journey.

The frontend must reinforce this identity everywhere.

Every page.

Every workflow.

Every interaction.

Every animation.

Every component.

Every piece of copy.

DESIGN NORTH STAR

The application should feel like:

A healthcare navigation operating system.

Not a healthcare dashboard.

Every screen should answer within two seconds:

Where am I?

What is happening?

Why does it matter?

What should happen next?

If a screen cannot answer those questions, redesign it.

ROLE-BASED OPERATING SYSTEMS

Each role must feel like its own operating environment.

Not the same dashboard with different labels.

Patient OS should feel like healthcare guidance.

Doctor OS should feel like care delivery.

Pharmacist OS should feel like medication coordination.

Hospital OS should feel like care infrastructure.

Organization OS should feel like traveler oversight.

Operator OS should feel like mission control.

Navigation Assistant should feel like an active healthcare coordinator.

Each role should have:

Unique hierarchy
Unique workflows
Unique layouts
Unique density
Unique priorities
RAYCAST PRINCIPLE

Do not copy Raycast.

Understand why Raycast works.

Raycast feels:

Fast.

Confident.

Purposeful.

Dense.

Intentional.

Every pixel earns its place.

Apply this philosophy to healthcare.

LINEAR PRINCIPLE

Linear is not visual inspiration.

Linear is UX inspiration.

Borrow:

Navigation
Workflow design
Hierarchy
Prioritization
Information density

The user should immediately know what requires attention.

CURSOR PRINCIPLE

The Navigation Assistant must not feel like ChatGPT.

The user should never feel they are chatting.

The user should feel the system is coordinating care on their behalf.

Good:

Reviewing nearby care options...

Checking language compatibility...

Contacting providers...

Waiting for response...

Provider confirmed.

Communication prepared.

Care journey ready.

Bad:

provider.search()

provider.assign()

provider.outreach()

Tool calls.

Execution logs.

Internal systems.

Never expose implementation.

Expose progress.

Before shipping any screen ask:

Would Raycast ship this?

Would Linear approve this workflow?

Would Stripe approve this documentation?

Would Apple approve this interaction?

Would a Staff Frontend Engineer approve this implementation?

Keep refining.

Not marketing art.

Build product simulations.

Animate workflows.

Animate outcomes.

Show systems working.

They should be watching SwasthYatra operate.
